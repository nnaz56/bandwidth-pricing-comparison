## 服务器带宽的两种计费模式，差别在哪

差别主要在计费对象和付费顺序上。按固定带宽是“先付费后使用”：你买 5M，平台就分配固定的 5M 出网带宽给你独享，费用合进云服务器账单一起收，适合网站这类需要 7×24 小时稳定对外服务的业务。按使用流量则是“先使用后付费”：先设一个带宽峰值封顶，再按实际产生的公网出方向流量收费，大陆多数地域 0.8 元/GB，每小时扣一次，账户里得留够余额。

两边还有一条容易被忽略的共同规则：计费只算出方向。用户上传文件到服务器的流量、内网互传的流量，都不收钱。

## 为什么入方向流量免费

因为云厂商只把出网带宽当作收费资源。阿里云官方文档写得很明确：你购买的带宽值实际是出网带宽值，入网带宽免费，上限跟着出网走——出网不到 10M 时，入网最高给到 10M；出网超过 10M，入网上限和你购买的出网带宽一致。

这对建站是好消息：访客打开你的网页、下载你提供的文件，消耗的是出方向流量；你往服务器传代码、传素材，再大的量也不产生带宽账单。

顺带把换算关系放在这里，选带宽时用得上：1Mbps = 128KB/s，5Mbps = 640KB/s。也就是说 1M 带宽下，用户下载一个 1MB 的页面要 8 秒左右——这也是为什么纯图文博客 1–3M 就够，带大图的站点至少要往 5M 看。

有两个点值得盯着看。一是 5M 到 6M 这一档：带宽只多了 1M，月费却从 125 元跳到 205 元。业务量在 5M 附近徘徊的话，先按 5M 买、用流量计费模式顶住峰值，往往比直接上 6M 划算。二是地域差价不小：同样 1M 固定带宽，青岛 20.7 元/月，吉隆坡 22 元/月，东京 25 元/月，香港 30 元/月，美国 30 元/月——服务器放错地域，等于花同样的钱少买三分之一的带宽。

以上是标准价，下单时系统会按购买时长给折扣。大厂也常有特价活动机：3M 固定带宽的云服务器见过 99 元/年、5M 见过 199 元/年的活动价，轻量应用服务器甚至有 38 元/年、自带 200M 峰值带宽的，具体以活动页当时的价格为准。

顺便看一眼海外厂商的算法。微软 Azure 的逻辑不同：数据传入免费，每月前 100GB 流出流量对所有客户免费，超出后按阶梯计费——从北美、欧洲流出到任意目的地，接下来 10TB 内每 GB 0.087 美元，用量越大越便宜（最低到 0.05 美元/GB）；亚洲（中国除外）、大洋洲、中东和非洲方向起步 0.12 美元/GB。同大洲区域之间传输更便宜，北美和欧洲区域之间 0.02 美元/GB，亚洲区域之间 0.08 美元/GB。如果你的用户在海外、月出流量又在 100GB 以内，出流量这项开销在 Azure 上基本为零；流量再往上走，就要拿它的阶梯单价和阿里云海外地域（0.5–0.6 元/GB）放在一起比了。Azure 价格以美元计价、随汇率浮动，官网价格页也注明仅是估算值。

## 固定带宽和按流量，到底哪个划算

卡在一条线上：**每月出方向流量 156GB**。5M 固定带宽包月 125 元，125 元除以 0.8 元/GB 等于 156GB——月流量低于这个数，按流量计费更便宜；高于它，固定带宽开始省钱。

往极端里算一笔账更能看出差距：5M 带宽满速是 640KB/s，一个月 2592000 秒全跑满，产出约 1582GB 流量，按流量计费要付 1265 元，是包月的十倍。当然没有站点天天满速，这个数字的意义在于提醒：下载、视频、图床这类流量型业务如果按流量计费，账单很容易失控。

还有一个只写在官方文档里的细节：按流量计费模式下，出入带宽峰值只是上限，不作为业务承诺指标，出现资源争抢时可能被限速。业务对带宽稳定性有要求，就得按固定带宽计费。

## 价格表之外的四个细节

**按量计费的固定带宽，短期用很灵活。** 除了包年包月，带宽还能按小时买：1–5Mbps 约 0.0625 元/Mbps/小时，6M 及以上 0.25 元/Mbps/小时。一台 5M 机器开满一个月约 225 元，比包月的 125 元贵，长期用不划算；但做三天压测、跑一周活动，用完就释放，比包月省得多。

**账户有限速策略。** 从 2020 年 11 月底起，单个地域下所有按流量计费实例的带宽峰值总和不超过 5Gbps，按固定带宽计费的不超过 50Gbps。批量开机器做业务的，先算算自己会不会顶到这条线。

**免费 DDoS 防护有 5Gbps 上限。** 云安全中心默认提供最大 5Gbps 的流量攻击防护，超过阈值实例会进入黑洞隔离。带宽买得再大，被打超了照样断网——这条和价格无关，但和“带宽能不能用”有关。

**6M 以上的天价带宽有替代方案。** 固定公网 IP 的带宽峰值一般最高可选到 200Mbps，再往上要走 EIP 或共享带宽。大带宽需求可以先看共享带宽（同地域多个 EIP 复用一条带宽计费）和共享流量包（套餐抵扣流量费），再配合 CDN 把静态资源分流出去，真正回源到服务器的流量能砍掉大半。

## 不同业务该配多大带宽

先给结论：图文博客 1–3M，企业站 3–5M，大流量业务先算流量账再决定买不买固定带宽。

- **个人博客、作品集**：1–3M。页面压缩后多在几十到一两百 KB，1M 的 128KB/s 扛日常访问没问题，月费 23–71 元。
- **企业官网、小程序后端**：3–5M。96–125 元/月，能应付并发稍高的场景。
- **图床、下载站、视频类**：6M 以上单价翻 3.5 倍，更常见的做法是 CDN + 按流量计费的组合，而不是硬买大带宽。

粗略估法：日均 PV × 页面平均大小 ÷ 86400 秒，得出平均带宽，再乘 3–5 倍预留峰值。比如日 PV 一万、页面平均 1MB，日均 10GB 流量，平均带宽不到 1Mbps，峰值预留 3–5M 就比较稳。

## 常见问题

**1M 带宽能带动多少人访问？**
按 128KB/s 的下载速度估算，页面平均 100KB 的话每秒能服务一个多请求；以文字为主的博客撑起日均几千的访问量问题不大，页面一旦有大图或下载资源，体验会明显下降。

**上传文件到服务器要收流量费吗？**
不收。流量计费只统计公网出方向的流量，往服务器上传数据、内网互传都免费。

**为什么 6M 带宽比 5M 贵这么多？**
固定带宽是阶梯定价：5M 及以内单价 23 元/M/月，6M 起涨到 80 元/M/月。5M 到 6M 只差 1M，月费却多 80 元。

**按流量计费会不会突然欠费？**
会。先用后付、每小时结算一次，余额不足会影响实例。建议给带宽设峰值封顶并保持余额充足，突发流量大的业务尤其如此，不然一次流量异常就可能产生高额账单。
